# Sub2API v0.1.171 Radar Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Integrate official Sub2API `v0.1.171` into the embedded Radar platform, prove migration and runtime compatibility, then promote a digest-pinned candidate through an isolated offshore trial.

**Architecture:** Start from the committed Radar v10 release head and preserve every dirty Radar change as an immutable patch plus an untracked-file archive. Merge the official tagged source in a clean integration worktree, resolve conflicts by ownership, then regenerate all Wire and Ent outputs. Deliver the result as control-plane and Worker OCI image digests, rehearse migrations using a disposable restore, deploy a fully isolated trial stack on the offshore host, and keep the prior v10 digests for image rollback.

**Tech Stack:** Go, Wire, Ent, PostgreSQL, Vue 3, TypeScript, Vitest, Python 3.11+, pytest, Docker Compose, Docker OCI digests, Bash, Nginx, Cloudflare Turnstile.

## Global Constraints

* Preserve the dirty Radar worktree exactly before any upstream merge. Never reset, clean, stash-pop into, or overwrite it.
* Use official Sub2API release commit `f0e7a9c7a23a7d02fb159b62fa809621eb0475a6` as the sole upstream source for `v0.1.171` functionality.
* Preserve `RADAR_LIFECYCLE_PROTOCOL_VERSION=2`, per-Worker tokens, internal-only Worker networking, read-only filesystems, capability declarations, and state volumes.
* Preserve all applied Radar migration filenames and bytes. The primary identity is the complete filename, including same numeric prefixes.
* Keep Radar embedded in the Sub2API SPA under `/admin/radar`; preserve `/model-health`; keep `radar.weihub.cloud` returning HTTP 410.
* Keep Turnstile enabled. `sub2api-staging.weihub.cloud` must be permitted at the CAPTCHA provider before login testing.
* Candidate tags use `0.1.171-radar-v11-YYYYMMDDTHHMMSSZ`. Every staging and production deployment uses an OCI digest, never a mutable tag.
* The 2 GB offshore host pulls verified images only. It does not build source images or share database, Redis, MinIO, ClamAV, or Worker volumes with production.
* Treat a checksum mismatch, migration failure, Worker protocol rejection, CAPTCHA failure, Radar HTTP 5xx, nonzero persistent outbox backlog, or restart increase as a promotion blocker.
* Keep credentials, Turnstile tokens, database dumps, API keys, Worker tokens, and private image registry credentials out of Git, command output, and evidence files.
* Every behavior change starts with a focused failing test and ends with focused plus relevant full verification.
* Set `RADAR_REGISTRY` to the approved registry host before image publishing. It contains a registry endpoint only and never a credential.
