# Sub2API v0.1.171 Radar Private GHCR Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish source-bound private GHCR images for the v0.1.171 Radar control plane and Worker, prove migration and rollback compatibility, run an isolated offshore trial, and promote only after every release gate passes.

**Architecture:** Harden the existing split Compose topology and release audits around two independently versioned OCI artifacts. Build both `linux/amd64` images locally from the final commit, deploy the exact digests to isolated rehearsal and trial projects, then reuse the accepted digests for production promotion and dual-artifact rollback.

**Tech Stack:** Docker Buildx and Compose v5, GHCR, Python 3.12+ audit tools and unittest, Bash release helpers, Go backend, Vue frontend, PostgreSQL 18, Redis 8, Python Worker with uv lock data.

## Global Constraints

- Design authority: `docs/superpowers/specs/2026-08-07-sub2api-v0.1.171-radar-private-ghcr-release-design.md`.
- Existing production projects `sub2api` and `sub2api-radar` remain unchanged until rehearsal and offshore trial gates pass.
- Candidate repositories are exactly `ghcr.io/a895411690/sub2api-radar-control-plane` and `ghcr.io/a895411690/sub2api-radar-worker`.
- Every accepted image reference is a repository, `@sha256:`, and exactly 64 lowercase hexadecimal characters.
- Control-plane and Worker candidate, active, rollback, and final digests are recorded separately.
- All release images target `linux/amd64`; the 2 GB offshore host never builds a candidate.
- Trial project and resource prefix are exactly `sub2api-radar-v11-trial`.
- Rehearsal project and resource prefix end with `-rehearsal` and never share production storage.
- Registry credentials, `.env` values, API keys, database contents, and backup contents never enter logs or evidence.
- Git commands in this worktree use `GIT_INDEX_FILE=/private/tmp/radar-v11-index-20260807` because the default index is stale.
- Build both candidates only after Tasks 1 through 6 are committed. Record the resulting final source commit, not the pre-hardening commit.
- Production mutation requires a fresh backup, restore proof, accepted trial evidence, dual rollback availability, and explicit action-time authorization.
