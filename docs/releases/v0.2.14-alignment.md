## XLSX security remediation

The original production-dependency audit reported two high-severity XLSX advisories, and the exception checker rejected both exceptions expired on 2026-10-06. The fix upgrades the same library from npm's unmaintained 0.18.5 to the official SheetJS 0.20.3 tarball, rather than renewing exceptions:

| Advisory | Official fixed version | Installed version |
| --- | --- | --- |
| [GHSA-4r6h-8v6p-xvw6](https://github.com/advisories/GHSA-4r6h-8v6p-xvw6) (CVE-2023-30533) | 0.19.3 | 0.20.3 |
| [GHSA-5pgg-2g8v-p4x9](https://github.com/advisories/GHSA-5pgg-2g8v-p4x9) (CVE-2024-22363) | 0.20.2 | 0.20.3 |

The dependency uses the exact URL documented in the [official NodeJS installation guide](https://docs.sheetjs.com/docs/getting-started/installation/nodejs/). The lockfile pins its SHA-512 integrity to `sha512-oLDq3jw7AcLqKWH2AhCpVTZl8mf6X2YReP+Neh0SJUzV/BdZYjth94tG5toiMB1PPrYtxOCfaoUCkvtuH+3AJA==`. Installed CommonJS, ESM, and TypeScript declaration files match the downloaded official package byte for byte. pnpm 9.15.9 frozen installation succeeds. This URL is a build dependency; browsers load the bundled local asset, not a runtime CDN script.

Source inspection finds a single non-test XLSX import in `frontend/src/views/admin/UsageView.vue`, used to construct and write an administrator usage export. No `XLSX.read` entry point was found. `/admin/usage` requires an authenticated administrator in the frontend router, and the backend usage routes are registered under the `/admin` group with `AdminAuthMiddleware`. These source checks do not replace production role-specific acceptance.

Only the two XLSX exceptions are removed. After the dependency upgrade, `pnpm audit --prod --audit-level=high --json` reports zero high/critical findings and neither XLSX advisory; the exception checker passes. Existing production-dependency findings remain (13 moderate and four low in this audit). Development-tool findings from the full dependency audit are outside this focused remediation and are not claimed resolved.

The existing XLSX writer and ordinary-user CSV exporter are unchanged. Administrator regression tests now decode real exported workbooks instead of mocking XLSX. They verify the 33 columns, four separate model-audit fields, numeric cells, cost precision, Unicode, pagination, headers-only exports, cancellation, later-page failures, and six formula-like prefixes across user-controlled text cells. The ordinary-user CSV formula-escaping tests still pass.

The before/after security proof combines the actual installed package identity, official affected-version ranges and changelog, production audit, and existing exception checker. No malformed-file exploit was exercised against the application because it exposes no spreadsheet-reading path; this does not claim a previously demonstrated application exploit. The compatibility and bypass review was performed in the main session, not by an independent reviewer.
